Technical Summary
The implementation is a FastAPI and Streamlit SDR workflow backed by Pydantic contracts, SQLAlchemy repositories, Apollo.io discovery, SearXNG/OpenSearch enrichment, LightGBM-based intelligence, MetaRank-ready feedback, Temporal workers, Brevo email, structured LLM conversation handling, and meeting/CRM provider adapters.
1. Runtime Architecture
Streamlit UI   -> FastAPI SDR backend :8011   -> ICP, Discovery, Enrichment, Intelligence, Qualification, Outreach APIs   -> Temporal workers for follow-up and meetings   -> SearXNG/OpenSearch for live enrichment   -> MetaRank for SDR queue reranking   -> Brevo, Google Calendar/Cal.com, Twenty CRM provider adapters

3. Apollo Configuration
SDR_DISCOVERY_PROVIDER=apollo_api SDR_DISCOVERY_APOLLO_API_KEY=your_apollo_master_api_key SDR_DISCOVERY_APOLLO_BASE_URL=https://api.apollo.io SDR_DISCOVERY_APOLLO_ALLOW_PUBLIC_FALLBACK=false SDR_DISCOVERY_ENABLE_WEB_SEARCH=false
Strict Apollo mode is the default: Apollo Organization Search and People API Search are used directly.
A 403 from Apollo means the key or plan is forbidden from that API endpoint, not that the local pipeline failed.
Set SDR_DISCOVERY_APOLLO_ALLOW_PUBLIC_FALLBACK=true only when you want Apollo-first fallback for demos.
Set reveal flags only if the Apollo plan and credits support email/phone enrichment.

7. Production Readiness Notes
Apollo access must be validated with the customer’s actual Apollo plan before live demos.
Bootstrap LightGBM models should be retrained on real SDR outcome labels before production scoring claims.
MetaRank should receive ranking and interaction events before being treated as the main ranker.
PostgreSQL migrations should replace local SQLite for production state.
Provider credentials must stay in backend environment variables or secret stores, not UI fields.
8. Marketplace and Shopify (Store Backend)
Files: app/models_market.py, app/services/shopify.py, app/routers/marketplace.py, Streamlit pages page_sell and the Admin Sellers tab.
Wiring: main.py imports models_market and includes marketplace.router; services/orders.py calls shopify.sync_order_stock after an order is marked paid.
Environment: SHOPIFY_API_SECRET (webhook signing secret), SHOPIFY_API_VERSION (default 2025-07).
Endpoints: POST /sellers, GET /sellers/me, GET /sellers/{slug}/products, PUT /sellers/me/shopify, POST /sellers/me/shopify/import, POST /webhooks/shopify, GET /admin/sellers, POST /admin/sellers/{id}/status.
Shopify webhooks to register: products/create, products/update, inventory_levels/update pointing at /webhooks/shopify.
Security: HMAC-SHA256 verification on the raw body, *.myshopify.com domain allowlist, pagination restricted to the shop host, webhook de-duplication via webhook_events. Access tokens are plaintext today and must be encrypted before production.
Tests: tests/test_marketplace.py (Shopify calls are monkeypatched).
Handoff from the SDR flow is a process step today, not an API integration.
